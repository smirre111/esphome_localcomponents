# MAC wire v1 (S8 / W4): the tests that are NOT run in a PROTO_SIM_MAC_WIRE_V1=ON
# (default) build, one "<executable> <Suite.Name>" per line, each with its reason.
#
# They pin v0 ENVELOPE bytes that v1 cannot express (a protobuf header with
# varints, duplicated or unknown fields, FrameCanon's re-encode check). They
# still run, unchanged, in the OFF build (the v0 path stays compiled until W5,
# which deletes them with it). Every other hub test runs in ON: the listener
# tests through sim/v1_bridge.h (v0-built uplinks become the v1 frames a real
# node sends; hub downlinks are inspected through their v0 view), the tracker
# tests through wire-aware frame builders, seam_test / e2e_test with the real
# node built v1. The node-harness targets (real_cmd_dispatcher_test,
# real_lora_interface_test) build the node with its v0 path in both
# configurations; the node repo covers the node's v1 path.
#
# Reasons (the v1 counterpart that covers the behaviour, where there is one):
#   APadded...  : a duplicated header field (v0 varint padding). v1: the header
#                 is fixed-size and the tag covers the on-air length
#                 (MacWireV1Listener.AV1FramesLengthIsExactSoFrameCanonHasNothingToDemote).
#   UnknownField: an unknown v0 field outside the CMAC. v1: every byte is under
#                 the tag; an unknown body field is inside it.
#   HeaderWider : a v0 varint burstIndex > 255. v1: a one-byte field, cannot
#                 be encoded (macwire::decode / encodeHeader tests, node repo).
