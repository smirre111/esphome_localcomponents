### 1. Plaintext uplinks are acted on while the session is confirmed — High

**Where.** `lora_client.cpp:1758–1801`: on a confirmed session a plaintext frame is
held only to a msgid high-water mark (`:1788`), then goes to `dispatch_payload_`
(`:1799`) and to every cover component. `dispatch_payload_` (`:1514`) routes a
`CommandAck` to `notePhaseReport_` (`:3840`) and `handle_command_ack_` (`:2413`).

**What an attacker in radio range can do, with no key.** The msgid is plaintext in
every header, so beating the high-water mark is trivial.

* A forged `CommandAck` naming a msgid in the tracked command's range cancels its
  retransmissions and clears "command failed" (`:2445–2455`). A real command can be
  lost while Home Assistant shows success.
* The same ack for a `ScheduleConfig` push marks the schedule as landed and clears
  "Schedule Pending" (`:2430–2442`).
* The same ack for a GridSync stops the re-publish (`:2416–2426`).
* The ack's `PhaseReport` is stored unconditionally (`:3850–3857`). A forged
  `timedRxActive = true` can move the hub to single-shot for a node that is not in
  Mode B. Rule 4 bounds this to one frame per command, but it contradicts the plan's
  statement that the report is authenticated by a GCM tag.
* A forged `GridSyncRequest` costs one GridSync burst a minute (bounded by
  `hubAnswersSyncRequest`) — added today, same hole.
* `CoverPosition` and battery frames are forwarded to the cover components.

**Fix direction.** Mirror the node's default-deny: once `session_confirmed_`, drop
every plaintext uplink except REGISTER and LOGIN before `dispatch_payload_`. Tests:
a forged plaintext ack neither cancels a tracked op nor changes the phase belief; the
same frames still work while no session exists.

### 2. Header timing fields are not authenticated — High

**Where.** The AAD is `destAddress ‖ destSubnet ‖ senderAddress ‖ msgid` only
(`FrameCrypto.h:23–24`, `buildAad :74–82`). The hub writes `burstIndex`, `onMark`,
`fireStamped`, `fireRound` and `fireOffsetUs` into each copy's outer header at
transmit time and re-packs it around the same ciphertext
(`lora_tracker.cpp:1151–1184`).

**What the node does with them.** Phase samples, the settled re-solve of a
provisional anchor, the burst back-out, and since fw 1.0.93 the trial re-centre all
read these fields. The phase block (`CmdDispatcher.cpp:4858`) runs *before* the msgid
replay check (`:5041`), so a replayed genuine encrypted copy passes the GCM tag check
and reaches it.

**Effect.** Replaying genuine copies with rewritten stamps into a node's (predictable)
mark window can poison its phase statistics, block promotion, or — with the re-centre
— walk its anchor. The fallback is Mode A, the safe direction, but Mode B can be denied
at will.

**Fix direction.** Short term, on the node: feed phase and anchor only from the frame
being accepted now — a msgid above the replay counter, or a copy of the msgid just
accepted within its burst span — never from an older msgid. Longer term: authenticate
the timing claim itself, either by including the per-copy fields in the AAD (one GCM
operation per copy) or by a short per-copy CMAC under the session key.

### 3. A window end can close a window whose frame is being read — Medium (latent)

**Where.** `LoraInterface::windowEndClosesWindow` (`LoraInterface.cpp:315–349`) relies
on "the DIO0 task clears ValidHeader/RxDone only after `noteRadioSlept`". That is not
true: `serviceDio0Event` calls `lora_parsePacket(flags, 0)` (`frtosTasks.cpp:341`),
whose first act is `lora_clearInterrupts(irqFlags)` (`lora.cpp:583`). The FIFO read,
`lora_sleep` and `noteRadioSlept` come afterwards, in `onReceiveNew`.

**Why it can happen.** The DIO0 task (priority 8) and DIO1 task (priority 7) share
core 1 (`main.cpp:407–423`), and `spi_device_transmit` blocks the caller for every
single-register transfer of the FIFO read. A window end pending in that gap sees clear
flags, a modem no longer receiving and an unchanged generation, and closes the window:
it books a missed mark for a received frame, sleeps the radio (the SX1276 clears its
FIFO in sleep) while the DIO0 task is still reading, and gives the radio semaphore a
second time. The extended timer ends 58.9 ms into a window and a 58-byte frame's RxDone
lands ~57 ms in, so the timing is realistic. fw 1.0.91 showed 0 false closes in ~390
windows, so the gap is narrow, but the guarantee does not exist.

**Fix direction.** Move the window generation on (and stop the window-end timer) at the
start of `serviceDio0Event`, before `lora_parsePacket`; additionally refuse to close
unless the op mode is still RxContinuous. Test with the recorder: flags cleared, radio
in standby, then a window end — nothing closes.

### 4. A window extends without limit — Medium

**Where.** `LoraInterface.cpp:339–346`: any window end with RegModemStat bit 0 ("signal
detected") set re-arms the timer for another 29.44 ms. Nothing caps it; only the 1 s
stuck-window recovery (`kStuckWindowUs`, entered after a 700 ms semaphore wait) ends it.

**Effect.** Persistent in-band interference can keep a window open for over a second,
burning receive current and skipping the Mode A windows in between.

**Fix direction.** Cap extensions at what the longest downlink can need (its airtime
over the window width, ~4), and extend on bit 0 alone at most once; count cap hits.

### 5. A non-addressed frame leaves the mark open — Medium

**Where.** `noteMarkArmed` sets `mark_window_open_`; only `noteMarkHit` (addressed
frame) and `noteMarkMissed` (empty close) clear it (`CmdDispatcher.h:325–350`). The
DIO0 path clears nothing.

**Effect.** A mark window that receives a CRC-failed or a neighbour's frame leaves the
flag set. The next window that closes empty — a Mode A, beacon or Class A window that
was never a mark — calls `noteMarkMissed` and counts toward demotion. Separately, the
comment says a miss is "no frame addressed to me", but only empty windows count, so a
node that keeps hearing a neighbour instead of its own frame never demotes on missed
marks.

**Fix direction.** Decide the mark's outcome when its window closes, whichever path
closes it, and align the code with the stated rule.

### 6. Unlocked window generation — Low

`window_gen_` is a read-modify-write `volatile uint8_t` (`LoraInterface.cpp:263`,
`:597`) written from core 0 (arming) and core 1 (DIO tasks). A lost bump lets a stale
window end match a newer window. Use `std::atomic<uint8_t>` or a spinlock.

### 7. Reservation eviction — Low

`LORATracker::reserve_` (`lora_tracker.cpp:888–897`) overwrites the entry with the
earliest end when all eight are used, even if that entry is still in the future. Fine
while few spans are outstanding (marks are placed one at a time); unproven for bursts
queued in quick succession. Evict only expired entries and log when full.

### 8. NULL string in the config save — Low

`ConfigStore.cpp:341–342`: `strlen(cJSON_PrintUnformatted(root))` before the NULL
check at `:362`, with the temp file already open. An allocation failure crashes the
save. The atomic rename itself is sound.

### 9. Re-centre inside a residual fit — Low

The ModeTest residual fit (`CmdDispatcher.cpp:2520`) predicts from the live anchor.
A node that re-centres during a test (not promoted) folds the correction into
`residualPpm`; the Mode B residual test was adjusted for this. Count re-centres in the
ModeTest report so a residual taken across one is recognisable.

## Checked and found sound

* SPI register access is serialised by a mutex per transaction (`lora.cpp:118–240`).
* `TICKS_TO_WAIT` is 1; no interrupt event is decimated with its pin left disabled.
* The node's unprovisioned-bootstrap exemption passes only ClientConfig and CoverConfig,
  only while its address is 0 (`CmdDispatcher.cpp:4801–4810`).
* The config save writes beside and renames over; LittleFS replaces the target.
* Protocol numbering: the new response field 23 (`GridSyncRequest`) and the operation
  field 23 (`GridBeacon`) live in different messages; a node or hub that does not know a
  new field ignores it.

## Known and accepted, not re-reported

* Plaintext `CMD_LOGIN` is the node's one deliberate exemption (plan, section 11b); a
  forged LoginMsg can still cost a session.
* A node without a fleet key accepts unsigned beacons (bounded re-anchor), and
  GridDemote is unauthenticated by design (safe direction).

## Scope and limits

Reviewed in depth: the node receive and window path (LoraInterface window code,
`serviceDio0Event`/`serviceDio1Event`, task placement), the trust placed in header
timing, hub uplink acceptance and dispatch, GridSync publish/re-publish/request, the
config save and the hub reservation table.

Not reviewed line by line: ModeTest internals, Mode C wake clock, auto mode and the
scheduler, AckCache and TxQueue, `lora_tracker` placement arithmetic beyond
reservations, `loracover`, and the YAML.

## Suggested order

1 and 3 first — both small and testable on the host. Then the short-term half of 2,
then 4 and 5, then the rest. None of them affects the running bench measurement; fw
1.0.93 should not go to a field node before 1 and 3.
